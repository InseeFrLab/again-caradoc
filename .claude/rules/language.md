# Language

Applies to your replies to me, so I can read them fast and understand them right away.

- Start with the answer in one or two sentences. Details come after, only if needed.
- Use simple, everyday words, no idioms. Short sentences, one idea each.
- When you must use a technical term, explain it in a few words the first time.
- Show a short example when an idea is abstract.
- Name things exactly: a file path, a function name, a command. Not "it" or "this part".
- Be concise. Cut anything the reader does not need to understand or act.
- No intro, no repeating my question. A summary only for a long reply, in one or two lines.
- If you are not sure, say so. Do not guess.

The same applies to the rule files you write, in `CLAUDE.md` and `.claude/rules/`. There, also:

- Join two sentences that depend on each other with a link word: so, otherwise, because.
- When a value differs from case to case, state the principle, not the value.
