# Database

The catalog is one PostgreSQL database, shared by all components. All its tables live in the default `public` schema.
Temporal has its own databases and its own role, on the same instance.

## Roles

A role is a database user: a login, plus the rights given to it.

- `catalog_owner` owns the database and its tables. Only the migrations connect with it.
- `catalog_writer` reads and writes rows. The Control API, the Query API and every worker connect with it. The Query
  API writes too: it stores the conversations.
- `catalog_reader` only reads. The Jobs API connects with it, and so does any other component that only reads the
  catalog.
- A new component gets no new role. It connects as `catalog_writer` if it writes the catalog, as `catalog_reader`
  otherwise.
- Rights are given once, on the whole schema, and a new table inherits them. Never write a `GRANT` for one table, one
  worker or one activity.
- The roles and the database are created outside the migrations, before the first one runs, since roles carry
  passwords. The database is created with `catalog_owner` as its owner. A migration never creates a role.
- The rights hold no secret, so the first migration gives them. It is written by hand and does nothing else: it sets
  the default privileges on the `public` schema, read and write for `catalog_writer`, read for `catalog_reader`. Tables
  start with the second migration, so the rights never share a file with autogenerated code.
- Each component reads its role's credentials from its settings. No running component holds the owner's credentials.
- In tests, the setup connects as `catalog_owner`. It builds the tables by running the migrations, never with
  `create_all`, since the migrations are what give the rights. The code under test connects as `catalog_writer` or
  `catalog_reader`, so a missing right fails in the tests.
- Ask before adding a role, a named schema or a grant, or changing the role a component connects with.

## Naming

- Table names are singular. A child table carries its parent's name: `job_document`, `document_change`.
- A date ends in `_at`. A lifecycle is `status`. A fact about a process ends in `_status`. A boolean is an adjective.
- A piece of data keeps one column name in every table. Example: if a file's size is `size_bytes` in one table, it is
  `size_bytes` in all of them, never `file_size`.
- A field written in a comment or a document carries its table: `job_document.status = failed`.

## Tables

- Every table has an `id` primary key: a UUIDv7, generated with `uuid.uuid7()`. Natural keys are unique constraints. A
  one-to-one table has its own `id` too, plus a unique foreign key.
- Every table has `created_at` and `updated_at`, timezone-aware, in UTC.
- A field has one value at a time. Two facts that can be true at once are two fields. Example: a source can be active
  and inaccessible at the same time. So `status` holds its lifecycle and `access_status` holds its access, never one
  enum with values like `active_inaccessible`.

## Enums

- Every status, type and reason code is a PostgreSQL enum.
- An enum value in `-ing` is work in progress. A value in `-ed` is a status a process reached. A plain adjective is a
  condition. Opposites read as opposites: `accessible`, `inaccessible`.

## Models

- Tables are `SQLModel(table=True)`. They live in one shared library under `backend/libs/`, since several components
  use them.
- Reach for `sqlalchemy` directly only when `sqlmodel` has no shortcut for it.

## Sessions and repositories

- A session always comes from a `transactional_session` block. The block commits when it ends cleanly, rolls back on an
  error, and always closes the session.
- A normal route takes `DatabaseSessionDependency`: one session for the whole request.
- A streaming route, a route that starts a job and an activity take the session factory and open their own sessions.
- Keep a session short: it holds a database connection, and locks on the rows it changed. Never keep one open during
  slow work, such as a download, a parse, a model call or a response stream. Read what is needed, leave the block, do
  the slow work, then open a new session to write the result.
- Never call `commit()` or `rollback()` on a session: `transactional_session` does both. If a manual commit seems
  needed, stop and ask.
- Catalog access goes through repository classes. A repository takes an `AsyncSession` in its constructor and never
  creates one. A method that loads one row returns the model or `None`. A repository calls `flush`, never `commit`.

## Migrations

- Only Alembic changes the structure of the database. Never create, change or drop a table, a column, an index or an
  enum type outside a migration.
- No component creates or changes a table at startup: no `SQLModel.metadata.create_all()`.
- There is one migration history for the whole catalog, kept with the models. Not one per component.
- Migrations always run as `catalog_owner`. The default rights apply only to tables that `catalog_owner` creates.
  Example: a table created by a migration run as `postgres` cannot be used by the writer or the reader ("permission
  denied"), and later migrations cannot change it.
- Alembic's `env.py` sees only the models it imports. A model it does not import is skipped by autogenerate, with no
  error.
- An autogenerated migration is a draft. Read it and fix it by hand before applying it. Alembic does not see
  everything:
  - A renamed table or column comes out as a drop and an add, which loses the data. Rewrite it as a rename.
  - A new value in an enum produces nothing. Add it by hand.
  - A changed server default produces nothing. Add it by hand.
  - A constraint without a name is not detected. Name every constraint.
- Never edit an applied migration. Write a new one.
- A migration must not break the code of the previous release, which still runs during a deployment and after a code
  rollback. So a rename or a removal takes two releases. Example: release 1 adds `size_bytes` and fills it, release 2
  drops `size`.
- Ask before anything destructive: a dropped column or table, a backfill of a non-null column.
